# CI 감사 보고서: 777hunter/hunter

조사일 2026-11-16. 읽기 전용으로 조사했고, 코드·워크플로·실행 기록은 하나도 건드리지 않았습니다.

## 한 줄 결론

이 저장소의 CI가 느린 건 아닙니다. 기록된 실행은 **전부 실패**입니다. 68회 모두 같은 원인으로 1초 만에 끝났고(Gemini 무료 등급 이미지 생성 한도 초과), 실제 작업에는 한 번도 도달하지 못했습니다. 시간 분석보다 이 실패가 먼저입니다.

## 범위

- 요청은 최근 150회였지만, 저장소 전체 실행 기록이 **68회**뿐이라 전부 분석했습니다. 기간은 2026-09-14 ~ 2026-11-15입니다.
- 실행된 워크플로는 `comic-news-card.yml` 하나입니다. 모두 `claude/news-card-august-1st-8ivdfe` 브랜치의 push로 시작했습니다.
- `daily-news.yml`(카카오 뉴스)과 `deploy.yml`(무음카메라)은 **한 번도 실행된 적이 없습니다**. 예약 실행과 main push 트리거는 기본 브랜치에 워크플로 파일이 있어야 동작하는데, 두 파일 모두 기능 브랜치에만 있습니다.
- 결과는 실패 67회, 취소 1회, 성공 0회입니다.
- 이 환경에서는 `gh` CLI를 검색 외 용도로 쓸 수 없어서, 같은 GitHub Actions API를 GitHub MCP 도구로 호출했습니다.

## 눈에 띄는 것

1. **실패율 100%, 원인은 하나.** 첫 실행(09-14)과 마지막 실행(11-15) 로그 모두 `gemini-2.5-flash-preview-image` 호출이 429 `RESOURCE_EXHAUSTED`로 실패합니다(일일·분당 무료 한도 초과). 마지막 실행의 재시도 대기 시간은 42,569초(약 11.8시간)였습니다. 무료 등급에서 이 모델은 사실상 쓸 수 없는 상태로 보입니다. 해결은 코드가 아니라 결제 등급이나 모델 선택의 문제입니다.
2. **실패한 날짜는 다시 만들지 않습니다.** 스크립트가 가장 최근 뉴스 파일 하나만 보기 때문에, 그날 실패하면 그 날짜 카드는 영영 생기지 않습니다. 지금까지 생성된 만화 카드는 0장입니다.
3. **한도 초과와 진짜 오류를 구분할 수 없습니다.** 429, 잘못된 키, 빈 응답이 모두 종료 코드 1입니다.
4. **Node 20 지원 종료 경고.** `actions/checkout@v4`와 `actions/setup-node@v4`가 Node 24로 강제 실행되고 있습니다. 당장 깨지지는 않지만, 다음 메이저 버전으로 올릴 때가 됐습니다.
5. **실패 실행을 시간마다 확인하는 예약 작업이 있습니다**("Re-check PR #1 CI", 1시간 간격). 원인이 외부 한도라 같은 결과를 반복 확인하고 있습니다.

## 속도 측면 권고 (우선순위 순)

속도는 문제가 아닙니다. 잡 하나가 12초이고 그 절반이 셋업입니다. `setup-node` 캐시를 붙여도 아낄 수 있는 건 실행당 2~3초입니다. 투자할 가치가 없습니다. 고칠 것은 실패 원인(1번)과 실패 날짜 재시도(2번)입니다.
