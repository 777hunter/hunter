# AI 기반 제조 수율 개선 기획

대상: 치과용 영상장비(파노라마/CBCT, 인트라오랄 센서, 디텍터 모듈) 제조 라인
작성: 2026-09-04 · 상태: 초안 (내부 검토용)

---

## 1. 결론 먼저

**권장 진입점은 "최종 영상 QC 이전에 불량을 예측하는 것"이 아니라, "디텍터 영상 판정 기준을 기계가 일관되게 유지하는 것"이다.**

이유는 데이터 물량이다. 의료영상장비는 연간 생산량이 수천 대 수준이고, 불량 모드별로 나누면 케이스가 수십 건에 그친다. 딥러닝을 돌릴 표본이 안 된다. 그런데 디텍터/센서 검사만은 예외다. 한 대가 플랫필드·팬텀 영상을 수십 장 만들고, 학습 단위가 "제품"이 아니라 "픽셀·패치"이므로 표본이 한 대당 수백만 개다. AI가 통계적으로 성립하는 유일한 지점이다.

따라서 순서는:

1. **디텍터 영상 결함 판정 자동화** (기술적으로 성립, 효과 즉시)
2. **불량 사유 텍스트 정규화** (LLM, 저비용, 파레토 분석의 전제 조건)
3. **상류 전기 검사 → 최종 QC 결과 예측** (Gradient Boosting, 데이터 축적 후)
4. **CBCT 지오메트리 캘리브레이션 드리프트 감지** (표본 확보에 가장 오래 걸림)

3·4번을 먼저 하겠다는 제안이 오면 반대해야 한다. 데이터 축적 기간이 최소 6~12개월 필요하고, 그 사이 성과가 안 나와서 과제가 죽는다.

## 2. 이 라인에서 통하지 않는 것

AI 수율 개선 사례는 대부분 반도체·디스플레이에서 나온다. 그 전제가 여기엔 없다.

| 반도체 전제 | 의료영상장비 실제 |
|---|---|
| 월 수만~수십만 장 웨이퍼 | 월 수백 대 |
| 공정 파라미터 수천 개가 자동 로깅 | 조립 공정 상당수가 수기 기록 |
| 불량 판정이 전수 자동 계측 | 최종 영상 QC에 사람 판단 개입 |
| 공정 변경이 사내 결정 | 제품 인수 기준 변경은 인허가 영향 |
| 재작업 불가, 스크랩 | 재작업 가능, 대신 공수 손실이 주 비용 |

마지막 두 줄이 핵심이다. **비용 구조가 스크랩이 아니라 재작업 공수와 리드타임에 있고, 판정 기준을 건드리는 순간 QMS 변경관리가 걸린다.** 이 두 가지가 과제 설계를 전부 결정한다.

## 3. 수율 손실 지도

먼저 채워야 하는 표다. 여기가 비어 있으면 아래 모든 계획은 추정이다.

| 공정 단계 | FPY | 주 불량 모드 | 발견 시점 | 처리 | 대당 손실 |
|---|---|---|---|---|---|
| SMT / PCBA | [ ] | 솔더, 부품 오삽 | ICT/AOI | 재작업 | [ ] |
| 디텍터 모듈 조립 | [ ] | 데드픽셀, 라인결함, 균일도 | 모듈 검사 | 스크랩/선별 | [ ] |
| X-ray 튜브·제너레이터 | [ ] | kV/mA 안정성, 아킹 | 전기 검사 | 재작업/교체 | [ ] |
| 갠트리·기구 조립 | [ ] | 회전축 정렬 | 최종 영상 QC | 재조정 | [ ] |
| 캘리브레이션 | [ ] | 게인/오프셋, 지오메트리 | 캘리브레이션 실패 | 반복 수행 | [ ] |
| 최종 영상 QC | [ ] | 아티팩트, MTF/CNR 미달 | 출하 직전 | 라인 역류 | [ ] |

**지금 확인해야 할 세 가지 숫자**

- RTY(Rolled Throughput Yield) — 단계별 FPY의 곱. 단계별로는 95%씩이어도 6단계면 74%다. 경영진이 보는 "최종 수율 98%"는 재작업 후 숫자라서 손실을 감춘다.
- **재작업 공수 총량** — 스크랩 금액보다 이쪽이 크면 과제 목표가 "불량 감소"가 아니라 "조기 발견"으로 바뀐다.
- **과검율(false reject)** — 최종 QC에서 사람이 보수적으로 반려한 뒤 재검에서 통과된 비율. 이 숫자가 5%를 넘으면 AI 적용 1순위는 불량 검출이 아니라 **판정 일관성**이다.

## 4. 적용 후보

### 4.1 디텍터 영상 결함 판정 자동화 — 1순위

**문제**: 플랫필드·팬텀 영상의 데드픽셀 클러스터, 라인 결함, 잔상, 균일도 편차를 검사자가 눈으로 본다. 검사자·시간대·피로도에 따라 합불 경계가 흔들린다. 경계선 패널이 어떤 날은 통과하고 어떤 날은 반려된다.

**접근**: 패치 단위 CNN 분류 + 이상 탐지 병행.
- 결함 유형이 명확한 것(데드픽셀, 라인)은 지도학습. 라벨은 기존 검사 기록에서 회수.
- 유형이 불명확한 것은 정상 패널만 학습한 오토인코더/PatchCore 계열 이상 탐지. 이쪽이 실전에서 더 중요하다. 새 불량 모드는 정의상 라벨이 없다.
- 출력은 합불이 아니라 **결함 맵 + 정량 지표**(클러스터 크기, 위치, 심각도). 사람이 최종 판정.

**왜 이게 성립하나**: 학습 단위가 픽셀/패치다. 패널 100장이면 패치 수십만 개. 표본 부족 문제를 유일하게 우회하는 지점.

**기대 효과**: 검출률 향상보다 **판정 산포 축소**에서 온다. 과검 감소분이 곧바로 수율이다.

**함정**: 게인/오프셋 캘리브레이션 전후 영상을 섞어 학습시키면 모델이 캘리브레이션 상태를 학습한다. 데이터 파이프라인에서 처리 단계를 반드시 고정할 것.

### 4.2 불량 사유 텍스트 정규화 — 2순위, 최저 비용

**문제**: 불량 사유가 자유 서술 한국어로 기록된다. "센서 이상", "센서불량", "detector NG", "화질 문제" 가 전부 다른 항목으로 집계된다. 파레토 차트가 안 나온다. 안 나오니 개선 우선순위를 감으로 정한다.

**접근**: LLM으로 과거 불량 기록 전체를 사전 정의 택소노미에 매핑. 신규 기록은 입력 시점에 후보 3개를 제안하고 작업자가 선택.

**왜 먼저 하나**: 2~3주면 끝나고, 이후 모든 분석의 전제 조건이며, 규제 리스크가 0이다(제품 인수 판정에 관여하지 않음). 과제 초기에 눈에 보이는 성과가 필요할 때 이만한 게 없다.

**주의**: 택소노미는 LLM이 만들면 안 된다. 품질팀이 정의하고 LLM은 매핑만. 자동 생성 택소노미는 현장 용어와 어긋나서 아무도 안 쓴다.

### 4.3 최종 QC 결과 조기 예측 — 3순위

**문제**: 갠트리 정렬 불량, 캘리브레이션 한계 등이 최종 영상 QC에서야 드러난다. 그 시점엔 이미 완제품 조립이 끝나 있어서 분해·재조정 공수가 크다.

**접근**: 상류 데이터(전기 검사값, 캘리브레이션 잔차, 부품 로트, 작업자, 설비)를 입력으로 최종 QC 합불을 예측하는 Gradient Boosting(XGBoost/LightGBM). 표본 수백~수천 건에서 동작하고, SHAP로 기여 인자를 볼 수 있어 엔지니어가 납득한다. 딥러닝 쓰지 말 것 — 표본 대비 과적합이고 설명이 안 된다.

**전제 조건**: 유닛 제네알로지. 완제품 시리얼 → 하위 모듈 시리얼 → 공정 파라미터 → 검사 결과가 하나의 키로 이어져야 한다. **이게 안 되어 있으면 이 과제는 시작할 수 없다.** MES/ERP 현황 확인이 선행 작업.

**현실적 목표**: 정확도가 아니라 **고위험 유닛 상위 10% 리콜(recall)**. "이 유닛은 최종 QC 위험이 높으니 조립 전에 캘리브레이션을 다시 보라"는 신호 하나면 충분하다.

### 4.4 CBCT 지오메트리 드리프트 감지 — 4순위

캘리브레이션 잔차 시계열을 추적해 기구적 열화를 재구성 아티팩트 발생 전에 잡는다. 개념은 명확하지만 정상 드리프트와 이상 드리프트를 구분할 이력 데이터가 필요하고, 그건 수집부터 시작해야 한다. **지금 할 일은 데이터 로깅을 켜는 것뿐이다.** 모델링은 내년 과제.

## 5. 데이터 요건

| 항목 | 필요 형태 | 현황 확인 필요 |
|---|---|---|
| 유닛 제네알로지 | 완제품↔모듈↔부품 로트 연결 키 | MES 스키마 확인 |
| 검사 영상 | 원본(raw), 처리 단계 명시, 유닛 시리얼 태깅 | 보관 여부·기간 |
| 검사 수치 | MTF, CNR, 균일도, 데드픽셀 수 — 값으로 저장(합불 플래그 말고) | 값 저장 여부 |
| 캘리브레이션 로그 | 잔차·반복 횟수 포함 | 장비 로컬 저장분 회수 가능성 |
| 불량 기록 | 사유, 조치, 공수, 재작업 여부 | 자유 텍스트 → 정규화 대상 |
| 공정 파라미터 | 설비, 작업자, 시각, 환경(온습도) | 수기 기록 비중 |

**가장 흔한 실패**: 검사 결과가 합/불 플래그로만 저장되어 있는 경우. 측정값 없이는 경향 분석도, 예측도, 과검 판단도 불가능하다. 이건 AI 이전에 고쳐야 할 문제고, 사실 이것만 고쳐도 수율은 움직인다.

## 6. 규제·QMS 제약 — 과제 순서를 결정하는 조건

의료기기 제조다. ISO 13485 / MFDS·FDA·MDR 체계 안에 있다. AI 적용 방식에 따라 부담이 완전히 달라진다.

| 유형 | AI 역할 | 검증 부담 |
|---|---|---|
| A. 분석 보조 | 엔지니어에게 인사이트 제공, 제품 판정 무관 | 없음 |
| B. 의사결정 지원 | 검사자에게 우선순위·후보 제시, 최종 판정은 사람 | 낮음 (사용 절차 문서화) |
| C. 자동 판정 | AI가 제품 인수/거부를 결정 | 높음 — 공정 밸리데이션, CSV/CSA, 변경관리, 인허가 영향 검토 |

**설계 원칙: 최소 2년간 C로 넘어가지 않는다.** 4.1의 디텍터 판정도 "결함 맵과 정량 지표를 제시하고 사람이 판정"하는 B 유형으로 설계한다. 그래도 효과의 대부분(판정 산포 축소)은 확보된다. C로 넘어가는 순간 밸리데이션 공수가 개발 공수를 넘어서고, 모델 재학습 때마다 변경관리가 걸려 사실상 모델이 고정된다.

이 구분을 초기에 문서로 못 박아두지 않으면, 나중에 "이왕이면 자동 판정까지" 요구가 들어와서 과제가 인허가 이슈에 잠긴다.

## 8. ROI 계산 틀

연간 효과 = 스크랩 절감 + 재작업 공수 절감 + 과검 회수 + 처리량 증가

```
스크랩 절감 = 연간 스크랩 대수 × 대당 원가 × 감소율
재작업 절감 = 연간 재작업 건수 × 건당 공수(h) × 시간당 원가 × 감소율
과검 회수   = 연간 과검 대수 × 대당 마진 × 회수율
처리량 증가 = 확보 공수 ÷ 대당 소요 공수 × 대당 마진
```

경험적으로 이런 라인에서는 **재작업 절감과 과검 회수가 스크랩 절감보다 크다.** 재작업은 지표에 안 잡히지만 라인 캐파를 먹기 때문이다. 과제 정당화 논리를 스크랩 금액에만 걸면 숫자가 작게 나와서 승인이 안 난다.

투자 측면은 인력이 대부분이다. 데이터 엔지니어 1, ML 엔지니어 1, 품질·공정 엔지니어 파트타임. 인프라는 GPU 서버 1대 수준이면 충분하고, 영상 데이터가 사내에 머물러야 하므로 온프레미스가 기본값이다.

| 검사자 저항 | B 유형 고정. "판정 대체"가 아니라 "경계선 케이스 근거 제공"으로 포지셔닝 |
| 라벨 품질 | 기존 검사 기록 라벨은 검사자 편차를 그대로 포함. 경계선 케이스는 복수 검사자 재라벨링 |
| 모델 드리프트 | 부품 로트·공정 변경 시 성능 저하. 월 단위 모니터링 지표 사전 정의 |
| 인허가 영향 확대 | C 유형 전환 금지 원칙 문서화 |

## 10. 확인이 필요한 사항

이 문서는 업계 일반 구조를 기반으로 작성했다. 다음이 확정되면 우선순위가 바뀔 수 있다.

- 실제 단계별 FPY와 손실 금액 구성 (스크랩 vs 재작업 비중)
- 최종 영상 QC의 과검율
- MES 제네알로지 구현 수준
- 검사 영상 보관 정책 (원본 보관 여부, 보관 기간)
- 생산 물량 규모 (모델별 연간 대수)
- 기존 AOI/자동검사 도입 범위

특히 **스크랩 vs 재작업 비중**과 **과검율** 두 개는 4.1과 4.3의 순서를 뒤집을 수 있는 변수다.
